# 任务管理系统使用文档

## 1. 系统简介与访问

任务管理系统包含 **定时任务**、**调度器监控**、**节点管理** 三个子模块，位于左侧菜单 **任务管理** 下。

| 项目 | 说明 |
| --- | --- |
| 启动 | 项目根目录执行 `.\dev.bat`（后端 8000 + 前端自动启动） |
| 访问 | 浏览器打开前端地址（开发模式默认 `http://localhost:9527`） |
| 登录 | 默认超管账号 `admin / admin123` |
| 权限 | 任务管理菜单默认仅 **超级管理员（R_SUPER）** 角色可见；可在「系统管理 → 角色管理」中为其他角色勾选任务管理菜单 |

> 菜单为后端下发（dynamic 模式）。修改菜单后需在「系统管理 → 菜单管理」维护，或重新执行 `python manage.py seed_system`（会自动失效路由缓存）。

## 2. 定时任务

路径：**任务管理 → 定时任务**

### 2.1 查询与列表

- 顶部搜索栏支持按 **任务名称 / 任务状态 / 触发方式** 筛选，点击「查询」生效、「重置」清空条件
- 列表字段：任务名称、描述、任务类型、触发方式（含规则描述）、优先级（高=红/中=黄/低=灰）、状态（启用/停用）、下次执行时间、上次执行时间及结果
- 右上角「新增」「刷新」「列设置」可自定义显示列

### 2.2 新建 / 编辑任务

点击「新增」或在行内点「编辑」，抽屉表单字段如下：

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 必填，全局唯一 |
| 任务描述 | 建议填写，如「清理30天前的系统操作日志」（内置处理器会读取其中的天数数字） |
| 任务类型 | **内置函数**：执行系统内置处理器；**HTTP请求**：定时调用一个 HTTP 接口 |
| 内置处理器 | function 类型必选，当前支持：操作日志清理 / 健康检查 / 心跳演示 |
| 请求方法/地址/请求体 | http 类型必填地址，方法支持 GET/POST/PUT/DELETE/PATCH |
| 触发方式 | 三选一，见下表 |
| 优先级 | 高 / 中 / 低（仅作标识与排序展示） |
| 超时秒数 | 执行超过该时长记为 **超时**，默认 300s |
| 状态 | 启用后才会注册到调度器；停用即从调度器移除 |

**触发方式：**

| 方式 | 字段 | 示例 |
| --- | --- | --- |
| CRON 表达式 | 5 段式 `分 时 日 月 周` | `0 3 * * *` 每天 3:00；`*/5 * * * *` 每 5 分钟；`0 3 * * sun` 每周日 3:00 |
| 固定间隔 | 间隔秒数（最小 5s） | 适合轮询、心跳类任务 |
| 指定时间 | 具体日期时间 | 一次性任务；时间已过则不排期 |

### 2.3 行内操作

| 操作 | 说明 |
| --- | --- |
| 历史 | 打开该任务的执行历史弹窗（状态、耗时、执行节点、输出/错误详情），支持分页 |
| 测试 | 立即异步执行一次，约 1~2 秒后列表刷新可见结果 |
| 暂停 | 任务置为停用并移出调度器，下次执行时间清空 |
| 恢复 | 重新启用并注册到调度器，立即计算下次执行时间 |
| 编辑 / 删除 | 删除为软删除，同时移出调度器 |

## 3. 调度器监控

路径：**任务管理 → 调度器监控**，页面自上而下分为五块。

### 3.1 状态横幅

- 蓝色「调度器运行正常…」：一切正常
- 橙色「检测到 N 条异常报警…」：24 小时内存在失败/超时执行，请查看下方异常报警列表

### 3.2 搜索栏

按 **任务名称 / 任务状态（运行中/已暂停）** 过滤下方任务卡片，客户端即时筛选。

### 3.3 调度器控制栏

左侧三个状态徽标：**调度器**（运行中/已暂停/已停止）、**在线节点**（在线/总数）、**任务**（卡片数量）。

| 按钮 | 行为 | 可用条件 |
| --- | --- | --- |
| 启动 | 调度器停止时启动（运行中点击则为从数据库重载全部任务，用于「清空任务」后恢复） | 非运行中，或需重载时 |
| 暂停 | 全局暂停：所有任务暂停触发，已排期计划保留 | 运行中 |
| 恢复 | 恢复触发 | 已暂停 |
| 关闭 | 停止调度器进程内引擎（有二次确认） | 非停止 |
| 清空任务 | 移除调度器内全部任务注册（任务记录保留，可重新「启动」装载） | 非停止 |
| 控制台 | 打开实时日志弹窗：启动/执行/失败/控制操作流水，支持关键字过滤，3 秒自动刷新 | — |

### 3.4 任务卡片

每个任务一张卡片：状态圆点 + 名称 + 运行状态标签；触发规则与**下次执行时间**；按钮：暂停（或暂停态显示恢复）/ 测试 / 编辑 / 删除，与定时任务页联动。

### 3.5 监控指标

| 指标 | 含义 |
| --- | --- |
| 运行状态 / 运行时长 | 调度器引擎状态与本次启动以来的持续运行时间 |
| CPU / 内存占用 | 调度器所在后端进程的实时资源占用（psutil 采集） |
| 今日执行 | 最近 24 小时执行总次数 |
| 成功率 | 最近 24 小时 成功数 / 总数 |
| 平均耗时 | 最近 24 小时执行平均耗时 |
| 今日失败 | 最近 24 小时失败 + 超时次数 |

### 3.6 异常报警与最近执行日志

- **异常报警**：列出最近 24 小时失败/超时的执行（任务名、状态、时间、错误摘要），每 5 秒自动刷新
- **最近执行日志**：全局最近 8 条执行记录，5 秒自动刷新

## 4. 节点管理

路径：**任务管理 → 节点管理**

### 4.1 汇总卡片

节点总数 / 在线节点 / 禁用节点 / 总负载（所有节点当前执行数之和）。

### 4.2 节点卡片

| 字段 | 说明 |
| --- | --- |
| 在线状态 | 绿点 = 在线（心跳 30 秒内）；灰点 = 离线；「已禁用」标签 = 手动禁用 |
| 本机 | 调度器自动注册的本地节点（带「本机」标签，不允许删除） |
| 负载 | 当前执行数 / 最大并发数，进度条展示 |
| 最后心跳 | 最近一次心跳上报时间；远程节点显示「从未上报」表示代理未接入 |
| 禁用/启用 | 禁用后不参与任务分配；本机节点也可临时禁用（调度任务会失败并记录） |

### 4.3 负载均衡与故障转移

- 每次执行按 **轮询 + 最低负载优先** 在「启用且在线」的节点中选择执行节点
- 选中节点不可达（如远程节点未部署执行代理）时，自动 **故障转移** 到下一个在线节点，执行记录的输出中会标注 `[故障转移] A -> B`
- 远程节点接入方式：部署执行代理，定期调用 `POST /api/task/node/heartbeat/` 上报 `{nodeId, load, version}` 即可上线

## 5. 常见问题

**Q1：左侧看不到「任务管理」菜单？**
菜单按角色下发，当前账号需具有 R_SUPER 角色；或请管理员在「角色管理」中勾选任务管理相关菜单。修改后重新登录刷新。

**Q2：任务到了计划时间没有执行？**
依次检查：调度器监控页状态是否为「运行中」→ 任务状态是否「启用」→ 指定时间类任务的时间是否已过期 → 控制台弹窗中是否有注册失败日志。

**Q3：执行历史里状态「超时」是什么意思？**
实际耗时超过任务配置的「超时秒数」。内置函数仍会执行完成，只是被标记超时；可调大超时或优化处理逻辑。

**Q4：HTTP 任务一直失败？**
在执行历史的输出/错误中查看响应。常见原因：地址不可达（探针任务依赖本机 8000 端口后端）、超时时间过短、接口返回非 2xx。

**Q5：清空任务后如何恢复调度？**
点击控制栏「启动」，会从数据库重新装载所有启用任务。

**Q6：调度器关闭后重启服务会自动恢复吗？**
会。调度器随 Django `runserver` 自动启动（生产环境建议用 `python manage.py runscheduler` 独立进程），启动时自动装载所有启用任务。
