# 后端接口代码结构说明

> 适用于 `backend/api/` 包。本次整理将所有功能模块接口代码按业务域归类到独立文件夹，与系统管理模块的组织方式保持一致。

## 一、顶层布局

```
backend/api/
├── admin.py / apps.py / exceptions.py    # Django 应用级文件
├── scheduler.py                          # 调度引擎（任务域核心服务，独立组件）
├── urls.py                               # 路由注册（仅引用 views 聚合出口）
├── tests.py / tests_apis.py              # 测试
├── management/commands/                  # 管理命令（seed_system / watchmigrate / runscheduler）
├── migrations/                           # 数据库迁移
├── models/                               # 数据模型层（按域分文件）
├── serializers/                          # 序列化层（按域分文件夹）
└── views/                                # 视图层（按域分文件夹）
```

## 二、views 视图层

```
views/
├── __init__.py          # 对外聚合出口：urls/tests 只从这里导入，不感知内部文件结构
├── common.py            # 跨模块公共设施：响应封装(ok/fail)、分页、认证(require_auth/_issue_token)、
│                        #   操作日志、_CRUDMixin、AuthenticatedViewSet
├── auth/                # 鉴权域
│   ├── account.py       #   验证码 / 登录 / 登出 / 用户信息 / 健康检查
│   └── route.py         #   动态路由（constantRoutes / userRoutes / isRouteExist）
├── system/              # 系统管理域
│   ├── user.py role.py menu.py dept.py post.py
│   ├── dict.py config.py log.py
│   └── __init__.py
├── monitor/             # 监控域
│   ├── server.py        #   服务器信息（CPU/内存/磁盘/网络）
│   ├── cache.py         #   Redis 缓存管理（列表/删除/详情/分类汇总）
│   ├── file.py          #   文件目录浏览 / 下载
│   └── storage.py       #   存储配置（本地/OSS/COS/七牛）
└── task/                # 任务域
    ├── job.py           #   定时任务 CRUD + 暂停/恢复/立即执行
    ├── log.py           #   执行日志查询 / 清空
    ├── node.py          #   执行节点 CRUD + 心跳上报
    └── scheduler.py     #   调度器状态 / 控制 / 控制台日志
```

## 三、serializers 序列化层

```
serializers/
├── __init__.py          # 对外聚合出口
├── common.py            # 跨模块通用：PaginationMixin、IdNameSerializer
├── schemas.py           # APIView 文档 Schema 序列化器（横切关注点，仅供 @extend_schema 使用，
│                        #   不参与业务校验；覆盖鉴权/路由/监控/通用列表参数）
├── system/              # 与 views/system 镜像
│   ├── rbac.py          #   部门/岗位/角色/菜单/用户（相互引用密切，合为一个文件）
│   ├── dict.py          #   字典类型/字典明细
│   ├── config.py        #   参数设置
│   └── log.py           #   操作日志
└── task/                # 与 views/task 镜像
    ├── job.py  log.py  node.py
```

## 四、models 模型层

```
models/
├── __init__.py          # 对外聚合出口（makemigrations 依赖此处导入）
├── base.py              # BaseModel 抽象基类（软删除/审计字段/排序）
├── rbac.py              # RBAC 权限域：Department/Post/Role/Menu/User（原 auth.py 更名）
├── system.py            # 系统管理域：DictType/DictData/Config/OperationLog
└── tasks.py             # 任务域：TaskJob/TaskExecutionLog/SchedulerNode
```

> 模型规模较小（单文件即一域），采用域文件而非文件夹；`rbac.py` 原名 `auth.py`，
> 因其承载的是角色/菜单/部门等权限实体而非认证流程，故更名归位。
> 所有模型仍统一从 `api.models` 导入，数据库表名与迁移完全不变。

## 五、代码组织规范

1. **域划分**：以业务领域为单位建文件夹 —— `auth`（鉴权）、`system`（系统管理）、`monitor`（监控）、`task`（任务）。新增模块时新建同级文件夹，并在 `views/__init__.py`、`serializers/__init__.py` 聚合导出。
2. **文件命名**：views 与 serializers 按子域一一同名对应（如 `views/monitor/cache.py` 的序列化器定义放 `serializers/schemas.py` 或 `serializers/monitor/`）。文件名使用小写单词，不加 `_views` / `_api` 后缀。
3. **聚合出口**：每个包/子包的 `__init__.py` 只做聚合导出并维护 `__all__`。外部（urls.py、tests、管理命令）**只允许**通过聚合出口导入：`from api.views import UserViewSet`、`from ..models import User`。
4. **模块间依赖**：
   - 允许：业务模块 → `common.py` / `schemas.py` / `models` 聚合出口 / `serializers` 聚合出口
   - 禁止：业务模块之间横向 import（如 task 不得 import monitor 的内部文件）；需要共享的逻辑下沉到 `common.py`
   - 循环依赖规避：模块内部确需延迟导入的场景（如 `TaskJobSerializer.get_isRunning` 引调度引擎），放在方法内局部导入
5. **`__init__.py` 文件夹视图文件**：每个域的 `__init__.py` docstring 标注该域包含的子文件及职责，便于导航。

## 六、整理前后对照

| 整理前 | 整理后 |
| --- | --- |
| `views/monitor.py`（580 行混合 4 类功能） | `views/monitor/{server,cache,file,storage}.py` |
| `views/auth.py` + `views/route.py` | `views/auth/{account,route}.py` |
| `views/tasks.py`（157 行混合 4 类功能） | `views/task/{job,log,node,scheduler}.py` |
| `serializers/auth.py`（名不副实，实为 RBAC） | `serializers/system/rbac.py` |
| `serializers/system.py` | `serializers/system/{dict,config,log}.py` |
| `serializers/tasks.py` | `serializers/task/{job,log,node}.py` |
| `models/auth.py` | `models/rbac.py` |

## 七、兼容性说明

- `urls.py` 通过 `from . import views` 使用聚合出口，**零修改**
- `seed_system.py`、`runscheduler.py`、tests 均通过 `api.models` / `api.views` 导入，**零修改**
- `makemigrations --check` 无变更：模型重命名不涉及数据库（迁移以 `api.models` 命名空间为基准）
- 全量测试 51 个全部通过；`/api/health`、`/api/schema/`、`/api/docs/` 重启后实测 200
